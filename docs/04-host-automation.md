# Host automation (T5c-3)

Normative for `server/src/host/` and `server/src/tools/host.ts`. Owner decision 2026-10-27: BatutaMCP "includes" host automation: launch Live, new set, open, save, save as, and the export dialog. It lives only in the server, in one isolated module. The Remote Script never does any of it (docs/01-protocol.md section 7.15). Items marked [A] are assumptions about macOS or Live that only the owner test in Live (T9) can confirm.

## 1. Isolation rules

1. `server/src/host/runner.ts` is the ONLY file that may import `node:child_process`, and it imports only `execFile` (never `exec`, `spawn`, the sync variants or `fork`; never with a shell). The static test suite enforces this on the AST: any other file importing it fails, and inside `runner.ts` a namespace/default import, an alias, `shell` as a property name, a spread options object, a first argument other than the `binary` parameter, or `execFile` used without being called directly all fail.
2. The runner enforces its own contract, whoever calls it. `/usr/bin/osascript` runs only `-e` plus a script that is `===` one of the constant sources in `host/scripts.ts`, with exactly that script's arguments: the running check takes Live bundle paths matching `^/Applications/Ableton Live 12 (Suite|Standard|Lite|Intro|Trial|Beta)\.app$`; the menu script takes one of `new`, `save`, `export`; Save As takes an absolute path ending in `.als` and a flag `0` or `1`. `/usr/bin/open` runs only `-a` plus one of those six bundles and at most one absolute `.als` path. Any other binary or argv shape is refused before a process exists. `createExecRunner()` takes no parameters. The AST scan allows value imports of `host/runner.ts` only in `host/host.ts` (the two binary constants) and `tools/index.ts` (`createExecRunner`), unaliased; type-only imports are unrestricted. The exact scanner rules (test/helpers/ast-scan.ts, run over all of `src`): (a) the one `createExecRunner()` call in `src` is the right operand of `??` in `runner: <deps>.runner ?? createExecRunner()`, a property of the first object argument of `new HostService({...})` in `tools/index.ts`, where `HostService` is the unaliased value import from `host/host.js`; any other declaration or import of the name `HostService` (alias, local class, function, variable, default or namespace import, another module) is refused, so the call cannot be exported, stored, shared or handed to anything else; (b) `.runner`, `["runner"]`, any string literal `"runner"`, and destructuring or assignment patterns naming `runner` are refused everywhere except `host/host.ts`, with one exception: `tools/index.ts` may read `<deps>.runner` as the left operand of that same `??`; (c) inside `host/host.ts` the private field `#runner` may only be assigned as `this.#runner = options.runner` in the constructor and used as the callee of `this.#runner(...)`: it cannot be returned, passed, aliased, bound or called through `.call`. The real `execFile` call takes its options from `execOptionsFor(options)`. There is no second runner factory in `src` (a test greps for it); the timeout, output-limit and environment tests use a helper under `test/helpers/` that reuses the exported `execOptionsFor` and `resultFromExec`, so they cover the real options without osascript or open.
3. AppleScript sources are constant strings in `host/scripts.ts`. They are never built from model text. Every variable (application path, set path, action id) travels as a separate argv element and is read inside the script through `on run argv`. The script text is passed once as the value of `-e`.
4. No argv element after the script may start with `-`; all paths are absolute and validated before they get there.
5. Every call has a timeout (5 s running check, 10 s `open`, 20 s menu actions, 40 s Save As) and a combined output limit of 64 KiB (the process is killed on either). The environment is minimal and built by the module: `PATH=/usr/bin:/bin`, `HOME`, `LANG=en_US.UTF-8`; nothing is inherited.
6. The module never reads or writes the `.als` file itself. It only stats it (existence, regular file, owner, symlink) and hands the path to Live.
7. Host calls are serialized per service: a second call waits for the first to finish (success or failure).
8. A runner is injected (`HostRunner`: binary, argv, options, result). Tests use a fake one and never start a process.
9. No script types text or sends keys to another app. Narrow exception (T9n): `SAVE_AS_SCRIPT` has exactly two key events, Cmd-Shift-G and Return, only in its `pressKey` handler, which refuses to send unless Live is the frontmost process and its Save panel is open. A static test pins the count, the place and the guard; every other script must contain none.

10. One narrow filesystem-write exception (section 3.1): `server/src/host/last-app.ts` is the ONLY file that may create, rename or unlink files, and only the small `last-edition.json` in the runtime directory. The static scan allows `fs.writeSync`, `fs.renameSync` and `fs.unlinkSync` and the flags `O_WRONLY | O_CREAT | O_EXCL` only in that file; everywhere else the server stays read-only.

The runner contract (rule 2) pins what may run, not where: it does not enforce `host.set_roots`. The set-folder rules of section 5 are enforced by `host/host.ts` (`checkPath`) before any runner call.

## 3. Finding Live

Installed apps are looked up in `/Applications` only, by the fixed names `Ableton Live 12 <Variant>.app` for the variants `Suite`, `Standard`, `Lite`, `Intro`, `Trial`, `Beta` (the pattern `Ableton Live 12 *.app`, resolved against a fixed list: the module has no directory listing). Each candidate must be a real directory (not a symlink) owned by root or the user, whose `Contents` is a real directory and whose `Contents/Info.plist` (opened read-only with `O_NOFOLLOW`, at most 256 KiB, owned by root or the user) is a plain XML plist with `<key>CFBundleIdentifier</key>` followed by `<string>com.ableton.live</string>`. A binary plist cannot be read without starting a program, so it is refused. A bundle with the right name that fails this check is not used; when no bundle passes, the error is `not_found` with `details.reason = "unverified_bundle"` and the bundle names.

The target app of a call is chosen in this order:
1. Live apps that are running (one `osascript` call that asks, for each installed app path, whether `application <path> is running`; it does not launch anything). More than one running: `not_supported` (`details.reason = "multiple_live_running"`). One running: that app. An explicit `app` argument or `host.live_app` naming a different variant is refused (`different_live_running`): a second instance is never started.
2. Otherwise the explicit `app` argument (`chosen_by: "requested"`), else `host.live_app` (`config`), else with `auto` the edition of the last Remote Script connection when that app is still installed (`last_used`, section 3.1), else the first installed of Suite, Standard, Lite, Intro, Trial, Beta (`default`). A running app reports `chosen_by: "running"`. `launch_live` and `open_set` return `chosen_by`.
3. No installed app: `not_found` (`details.what = "live_app"`).

### 3.1 The edition of the last connection

Every successful Remote Script connection (welcome edition `lite`, `standard` or `suite`; `unknown` is ignored) is remembered in `<runtime dir>/last-edition.json`, `{"variant":"lite"}`, mode 0600, so that `auto` starts the edition the owner really works in instead of preferring Suite (owner finding F-T9-26). It is a hint only. The server never creates the runtime directory (the Remote Script does); it must pass the same checks as for the token (real directory, owner, mode 0700) or the hint is neither read nor written. Reading opens with `O_NOFOLLOW`, requires a regular file of the user without group or other bits, at most 256 bytes, and a JSON object whose `variant` is one of the six names. Writing creates `last-edition.json.tmp.<16 hex>` with `O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW` (0600) and renames it over the final name, so a symlink or directory at that name is never followed (a failed write removes its temporary file). Any failure means "unknown" and is silent. If the remembered app is no longer installed, the fixed order applies. `batuta_status` reports `host.last_used`.

## 4. Tools

All six are server-only (no Remote Script command), named in `docs/03-tool-names.md`, and work whether or not Live is connected to the Remote Script. Results are `structuredContent` plus a one-line text. Every call that reached execution is appended to the action log: tool name, the path (never file contents) and an `outcome` (`ok`, or the error code it ended with).

| Tool | Arguments | Does | Annotations (read-only / destructive / idempotent / open-world) |
|---|---|---|---|
| `launch_live` | `app?` (variant name) | `open -a <app path>`. Already running: activates it. Result `action: "launched"/"activated"`, `app`, `was_running` | false / false / true / false |
| `open_set` | `path` | `open -a <app path> <path>`. Live shows its own "save changes?" dialog when the current set has unsaved edits, so BatutaMCP does not ask (in `confirm:"destructive"` it does) | false / true / false / false |
| `new_set` | none | File > New Live Set by menu click on the Live process. Live's own dialog protects unsaved edits (same note) | false / true / false / false |
| `save_set` | none | File > Save Live Set by menu click. A set that was never saved makes Live open its Save dialog: result `result: "save_dialog_open"` and the model must tell the user (or call `save_set_as`) | false / false / true / false |
| `save_set_as` | `path` | Drives Live's Save As dialog (section 6). Asks for confirmation only when the target file already exists | false / true / false / false |
| `export_audio` | none | Opens Live's Export Audio/Video dialog (menu click) and stops. The user completes the export in Live | false / false / true / false |

`open_set` and `save_set_as` take the same `path` (section 5). Live is always given the real path (the realpath of the folder plus the file name), never the spelling the model used.

## 5. Path rules (`open_set`, `save_set_as`)

All must hold, checked again immediately before the action runs (also after a `batuta_confirm`):
1. A string, at most 1024 UTF-8 bytes, no control character (NUL has its own reason `nul_byte`) and none of the invisible, filler or direction characters U+00AD, U+034F, U+061C, U+115F/1160, U+17B4/17B5, U+180B-U+180F, U+200B-U+200F, U+2028/2029, U+202A-U+202E, U+2060-U+2069, U+2800, U+3164, U+FE00-U+FE0F, U+FEFF, U+FFA0, U+FFF9-U+FFFB, U+1D173-U+1D17A, U+E0000-U+E007F, U+E0100-U+E01EF. Summaries and the action log strip the same characters.
2. Absolute, already NFC (`path.normalize(p) === p` and `p.normalize("NFC") === p`: no `.`, `..`, `//` or trailing slash).
3. Extension `.als`, case-insensitive, with a non-empty base name.
4. The parent directory exists (`not_found`, `details.what = "parent_directory"`) and is a directory owned by the current user. When `host.set_roots` is non-empty (it is empty by default: no folder restriction), its `realpath` also lies inside the `realpath` of a configured root, the lexical parent lies inside the lexical root, and a symlink anywhere in the parent chain that leads outside the roots fails (`outside_roots`). With no roots there is no folder to walk down from, and none is needed: a save already requires `realpath(parent) === parent` (rule 7, so no component of the parent can be a symlink that redirects the write), and an open hands Live the real path (the realpath of the folder plus the file name), never the spelling the model gave.
5. The final component is never a symlink.
6. `open_set`: the file exists and is a regular file (`not_found`, `details.what = "set_file"`).
7. `save_set_as`: the folder must not be reached through a symlink (its realpath equals the given folder, `symlinked_parent`); if the file exists it must be a regular file with a single hard link (`hardlinked_file`); its existence decides the confirmation. The same rules apply to the second place Live may write, `<folder>/<name> Project/<name>.als`: a symlinked `<name> Project` folder or file is refused (`symlink_target`), and either file existing counts as "exists" (confirmation, replace flag). A file that appears or disappears between planning and execution is refused (`invalid_args`, `details.reason = "target_changed"`).

Failures are `invalid_args` with `details.reason`: `not_a_string`, `empty`, `nul_byte`, `control_character`, `too_long`, `not_absolute`, `not_normalized`, `not_nfc`, `wrong_extension`, `outside_roots`, `not_a_directory`, `not_owned`, `symlink_target`, `not_a_file`, `symlinked_parent`, `hardlinked_file`. `outside_roots` only occurs when `host.set_roots` is set. Race condition (TOCTOU) between the check and Live opening the path is not eliminated: it needs write access to a directory the user owns (inside the roots, when set).

## 6. UI scripting (all [A])

Menu actions target the Live process (`bundle identifier "com.ableton.live"` [A]) through System Events (`click menu item ... of menu "File" of menu bar 1`). The project forbids typing into other apps: no script types text, and the menu, running-check and every other script contain no key event. The one narrow exception is the Save As script (T9n): exactly two key events, Cmd-Shift-G (Go to folder) and Return, both in one handler (`pressKey`) that first checks that Live is the frontmost process (`name of first application process whose frontmost is true` equals Live's process name) and that the Save panel is open, and sends nothing otherwise (`live_not_frontmost`). All text is set through accessibility values, never typed. A test pins the count and the guard. Exactly one such process must exist: none gives `not_supported` (`live_not_running`, hint: call `launch_live`), several give `multiple_live_running`.

Menu titles are matched against fixed English and Spanish lists, after normalising both sides: case is ignored, a trailing ellipsis (`...`, any number of dots, or U+2026) and trailing spaces are dropped, repeated and non-breaking spaces become one space. The match is exact equality of the normalised text, never a prefix, so `Guardar Set Live` does not match `Guardar Set Live como...` or `Guardar una copia...`, and `Exportar Audio` does not match `Exportar MIDI Clip...`. The menu bar item is `File` or `Archivo`. Known titles (all normalised): new = `New Live Set`, `Nuevo Set Live`, `Nuevo Live Set`, `Nuevo set de Live`; save = `Save Live Set`, `Guardar Set Live`, `Guardar Live Set`, `Guardar set de Live`; save as = `Save Live Set As`, `Guardar Set Live como`, `Guardar Live Set como`, `Guardar set de Live como`; export = `Export Audio/Video` (Standard, Suite), `Export Audio` (Lite), `Exportar audio/video`, `Exportar audio/vídeo`, `Exportar Audio`. Titles in other languages, or a Live version that renames them, fail with `host_failed` (`details.reason = "menu_item_not_found"`); the error text and `details.looked_for` / `details.found` list the titles looked for and the File menu items found (at most 30, each cut to 80 characters), so a mismatch is visible. A disabled item gives `not_supported` (`menu_item_disabled`).

Save As, after the menu click:
1. Wait up to 7.5 s for the save panel: a sheet of any Live window, or a window of subrole `AXDialog` (observed on Live 12.4.7 Lite, macOS in English: a window named `Save`, not a sheet, with an `AXSplitGroup`) [A]. The panel's controls are not direct children of that window, so the script searches groups and split groups up to three levels down (H3, H5).
2. Never put the path in the name field (F-T9-23: macOS keeps the panel's current folder and saved a file named `:Users:...:a.als` there). Go to the folder first: bring Live to the front (an accessibility property), then, with Live frontmost and the panel open, press Cmd-Shift-G; a sheet with one text field opens on the panel. Set that field to the folder (the validated parent, absolute) by accessibility, check again that Live is frontmost, press Return. Wait for the sheet to close and for the panel's `Where:` pop up button (AXPopUpButton, found by name `Where` / `Donde` / `Ubicacion`, else the first pop up) to show the folder's base name. Only then set the name field (the text field titled `Save As:` / `Guardar como:`, else the first non-search text field) to the file base name only, read it back and compare. Right before Save, `Where:` and the name are read once more. If any check fails, the script cancels the go-to sheet and the panel (cancel button attribute, else Cancel / Cancelar), nothing is saved, and the call fails with `host_failed` (`path_not_applied`, with `details.where` and `details.name` as seen). Only after all checks click the default button (the `AXDefaultButton` attribute, else Save / Guardar). The macOS language of the panel does not matter. The panel is closed when no sheet or dialog window is left (not when a window index disappears). Residual risk: `Where:` shows a display name, so a different folder with the same base name would pass; the server's own post-save check (step 4) still requires the file inside the validated folder.
3. If a replace confirmation sheet appears: only in the branch where `allow_replace = "1"` (set only after the server confirmed an existing target) and only when the sheet's text contains the target's base name inside quotes (ASCII or curly), compared case-sensitively so `a.als` does not match `aa.als`, click Replace / Reemplazar; if the text does not name the file, click Cancel / Cancelar and fail with `host_failed` (`replace_unverified`). With `allow_replace = "0"` the script clicks Cancel / Cancelar only and fails with `host_failed` (`target_exists`). The word Replace / Reemplazar appears in the script exactly once, in the first branch (a test enforces it).
The script also refuses an empty base name (`bad_target`).
4. Wait up to 6 s for the dialog to close. Live writes `<folder>/<name> Project/<name>.als` (a Live Project folder it creates, with `Ableton Project Info` and `Icon`) when the folder is not inside a Live project, and probably `<folder>/<name>.als` inside one. The server checks both candidates (project candidate first) and reports the one that landed as `path` (`requested_path` holds the asked path when they differ). Each must be a regular file (not a symlink) in a real, non-symlink folder, whose modification time is not older than the start of the call and not more than 5 s in the future, with the expected real folder (the validated parent, or the `<name> Project` folder directly inside it), and, when it existed before, changed (new inode or modification time) compared with a snapshot of that candidate taken just before the call; otherwise `host_failed` (`save_unverified`, when neither candidate landed). Only then is `result: "saved"` reported. A dialog that never closes is a `timeout`.

   Replacing (T9o, F-T9-24): Live never shows a replace sheet when `<folder>/<name> Project` already exists; given `<folder>` and `<name>.als` it saves a new `<folder>/<name>-1 Project/<name>.als` (evidence H10, 2026-10-30, Live 12.4.7 Lite). So when only `<folder>/<name> Project/<name>.als` exists, the server passes that file to the script: the Go to folder step goes into `<folder>/<name> Project` itself, `Where:` must show `<name> Project`, the name is `<name>.als`, and Live shows its replace sheet for it, which step 3 completes. The confirmation names that file and the post-save check accepts only that file (changed inode or fresh modification time), reporting `replaced: true`, `path` the project file and `requested_path` the asked path. When the direct file `<folder>/<name>.als` exists (the folder is inside a Live project) the direct path is used as before. If the check fails and a `<name>-N Project` folder (N 1 to 20) holding the set appeared during the call, the error is `host_failed` with `details.reason = "stray_project_folder"` and `details.stray_path`; it is never reported as success and the expected file is untouched.

## 7. Permissions

UI scripting needs Accessibility for the app that runs the MCP client (and Automation access to System Events). Detection is by error number only, because the wording is localized: a number in parentheses at the end of a stderr line, -25211 or -1719 for Accessibility and -1743 for Automation. (-1719 is also what an invalid UI index reports; the scripts test with `exists` before every access so it should only appear when UI scripting is not allowed [A].) These map to the new error code `permission_required` with `details.permission` (`accessibility` or `automation`) and the instruction: System Settings > Privacy & Security > Accessibility (or Automation) > enable the app that runs the MCP client (Terminal, iTerm, Claude, ...), then retry. `launch_live`, `open_set` and the running check do not need either permission.

`batuta_status` / `health` report `host`: `enabled`, `live_app`, `apps` found, `selected`, `last_used` (the remembered edition, `null` when unknown or no longer installed), `running` (last known, `null` before any host call), `accessibility` (`unknown` until a UI action ran, then `granted` or `denied`), `set_roots_count`. They never start a process.

## 8. Confirmation policy (docs/01-protocol.md section 9.1a)

| Call | `confirm:"irreversible"` (default) | `confirm:"destructive"` | `destructive:"disabled"` |
|---|---|---|---|
| `launch_live`, `save_set`, `export_audio` | runs | runs | runs |
| `open_set`, `new_set` | runs (Live's dialog protects) | asks | runs |
| `save_set_as`, target absent | runs | runs | runs |
| `save_set_as`, target exists | asks (summary has the path; cannot be undone) | asks | refused: `not_supported`, `details.reason = "disabled_by_config"`, nothing runs |

Asking uses the normal mechanism (elicitation, else the single-use `batuta_confirm` token); the stored action is re-validated when released. The summary is built from static text and the validated path (long paths keep the last 300 characters).
