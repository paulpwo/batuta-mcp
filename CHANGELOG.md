# Changelog

All notable changes are documented here. The format follows Keep a Changelog and the project uses Semantic Versioning.

## [0.1.0] - Unreleased

First release.

### Added
- Remote Script for Ableton Live 12 (Python standard library only, runs inside Live's embedded Python 3.11): authenticated local AF_UNIX socket, allowlisted command dispatch, undo wrapping, output and size caps, and recording/browser safety rules. 86 commands covering transport, tracks (including master and returns), mixer, routing, scenes, cue points, clips and notes, envelopes, arrangement, devices, racks, drum pads, browser search/load and view switching.
- MCP server in TypeScript with zero runtime dependencies: own minimal stdio JSON-RPC layer, schema validator, socket client with reconnect and timeouts, and a tool surface of more than 120 tools with convenient aliases and composite tools (session snapshot, drum kit loading, locator upsert).
- Safety model: confirmation for destructive actions (MCP elicitation, or a single-use hash-bound token), Lite edition limits applied only on Live Lite, gain guards, and a static scanner that rejects dynamic code execution patterns.
- Host automation tools (launch Live, open/new/save/save-as set, export audio) through one isolated module with fixed, allowlisted invocations.
- Loudness engine: WAV/AIFF reader, K-weighted momentary/short-term/integrated loudness, loudness range, true peak and spectrum bands, validated against EBU Tech 3341/3342 style signals.
- Audio import (`create_audio_clip`) works without configuration for any absolute path to an existing regular audio file; the optional `sample_roots` setting narrows imports to those folders.
- Side-by-side installer that never deletes existing files and archives previous installs.
- Installer `link` command for development: symlinks `Remote Scripts/BatutaMCP` to the repo's Remote Script (an unmodified copy install is archived first, `install` replaces the link), with `status`/`verify` support.
- Status bar feedback: after each mutating command the Remote Script shows one short `BatutaMCP: ...` line in Live's status bar (command name and numbers only; refusals show the error code; read-only commands stay silent).
- Claude Desktop (macOS) support: the installer prints a ready-to-paste `claude_desktop_config.json` block (print only, it never touches that file) and `docs/02-install.md` has a Claude Desktop section.
- Base usage skill `skills/batuta-ableton` (addressing, confirmations, gain guard, undo, editions, host tools, ears, error codes) that `mixing-ableton` builds on, and a short `instructions` string in the MCP `initialize` result with the same core rules.
- Claude Code transport bar: the `batuta-transport` plugin ships in `clients/claude-code/` as a local marketplace (`batuta`); the installer prints the `claude plugin marketplace add` and `claude plugin install` commands (print only) and `docs/02-install.md` has a section.
- Packaging: MIT license, exact-pinned dev dependencies with lockfile, pnpm install-script blocking, CycloneDX SBOM, and CI.

### Changed
- Session ownership (T9f): the server no longer connects when the session starts; it connects on the first tool call that needs Live and gives the slot back after `live.idle_release_s` seconds without activity (default 120, `0` never). Another session's call is refused with `busy` / `details.reason: held_by_other_session` and never takes over; there is no auto-reconnect or socket polling while idle or released, and `batuta_status` reports `connection.state` `idle` or `released`. In-flight calls and running ears jobs keep the slot. The Remote Script is unchanged (a second client already got a `busy` frame).
- The Claude Code registration name is now `batutaMCP` (installer output, Claude Desktop block, docs); tools appear as `mcp__batutaMCP__<tool>`. The package, server name, runtime folder and temporary track names are unchanged. Register again with the new name and remove the old `batuta` entry.
- External-input acknowledgement hardened (T9s): a client that cannot ask now means refuse (no stored plan for `batuta_confirm`); the acknowledgement is bound to the exact tracks the question named (`external_input_ack: {tracks: [ids]}`, refused again with a new question if the set grew); a batch half-run by an op that changed the set reports `details.ops_run` and is not re-sent; the ears gate also names External devices; inserting or loading an External device while a recording is possible asks first; the question says `and N more` beyond eight tracks. `song_info` gains `external_live_tracks`. Script change: restart Live.
- Max for Live loads by default: new `browser.allow_max_for_live` (default `true`, sent to the Remote Script in `hello`). `.amxd` files, M4L names, the `max_for_live` browser category (listed, searched, descended), stock Suite M4L devices and racks holding Max devices load and are no longer swept; they report their real `class_name`. `false` restores the previous blocking exactly. Needs a Live restart for the Remote Script and an MCP reconnect.
- External Audio Effect / External Instrument load by default: new `browser.allow_external_devices` (default `true`); `false` restores the block. The recording rule changes with it: arming or monitoring In an audio track on an external input, starting a recording (record flags, session record, firing an empty armed slot or scene, playback with record flags on, ears) and duplicating an external-live track are now confirmable instead of final. The Remote Script still refuses by default (`details.acknowledgeable`); the server asks once, naming the tracks and warning that the recording may capture a microphone, and re-sends with the `external_input_ack` request flag on accept (decline cancels, no answer is the usual confirmation timeout). A batch needing it is refused whole before any op runs and asked once. The flag is never accepted as a tool argument. Audio tracks with a SAFE input and the ears track rules are unchanged.
- Works without configuration for sets anywhere: `host.set_roots` is optional like `sample_roots`. Empty (the default) means no folder restriction for `open_set` and `save_set_as` (before, only `~/Music/Ableton` and `~/Documents/PRODUCTION` were accepted, so sets on the Desktop were refused). The other rules stay: absolute normalized `.als` path, existing parent folder owned by you, a regular set file that is not a symlink, no symlinked `<name> Project` folder, no write through a symlinked folder, and replacing a file still asks. A non-empty `host.set_roots` narrows exactly as before.
- With Live closed, `launch_live` and `open_set` (`host.live_app: auto`) start the edition of the last Remote Script connection instead of preferring Suite. It is remembered in `last-edition.json` in the runtime folder (private file, never through a link) and used only when that app is still installed; an explicit `app` or `host.live_app` still wins. The results and `batuta_status` say why (`chosen_by`: `running`, `requested`, `config`, `last_used`, `default`; `host.last_used`).
- The server reconnects to Live within about a second of Live's socket appearing: while a long backoff delay runs it checks the socket once a second and reconnects as soon as the socket is created or re-created (before, a restart of Live could take about 40 s to be noticed).

### Fixed
- `save_set_as` over a set that Live saved in its project layout: when `<folder>/<name> Project/<name>.als` exists, the Save As panel is driven into the project folder itself so Live shows its replace sheet (before, Live silently created `<name>-1 Project`). The confirmation names the real file, the result reports `replaced: true`, and a stray `<name>-N Project` copy is reported by path as `stray_project_folder` instead of a generic failure.
- Found in Live 12.4.7 Lite with the Live UI in Spanish: `export_audio` and `save_set` failed `host_failed` ("Live's File menu does not have the expected item"). File menu titles are now matched after normalising case, trailing ellipsis (`...`, U+2026) and repeated spaces, by exact equality (so Save never matches Save As or Save a copy), with the real Spanish titles and the Lite `Export Audio` added. The Save As panel (a separate `AXDialog` window whose buttons and name field sit inside split groups) is found by role, default/cancel button attributes and English or Spanish names, in English or Spanish macOS. A missing item now reports the titles looked for and the File menu items found (`details.looked_for`, `details.found`).
- Found in Live 12.4.7 Lite: `load_drum_kit` on a track that already held a Drum Rack loaded the rack with no visible change, the post-load sweep timed out and the kit load was refused as busy, leaving the call half done. The tool now reads the track first and skips the rack load when a top-level Drum Rack instrument is present (`rack_load: {skipped: true, reason: "drum_rack_present"}`), and when its own rack load is still being swept it retries the kit load for a bounded time; if that is not enough it fails `busy` with `rack_loaded: true` and says to call again.
- Found in Live 12.4.7 Lite: loading the native Drum Rack onto an audio track made Live create a new armed MIDI track while the `load_instrument_or_effect` result said nothing. The result (and the sweep outcome of an asynchronous load) now lists such tracks in `new_tracks` with `landed_on`, plus a server warning; the track is left in place.
- Found in Live 12.4.7 Lite: `modify_clip_notes` failed with `apply_note_modifications ... did not match C++ signature`; it now edits the note vector Live returned (`get_notes_by_id`, else the extended read) and hands that same vector back.
- Found in Live 12.4.7 Lite: `start_playback` and `stop_playback` replied with the play state from before the change; the reply is now read one Live tick after the write. `cue_create` and `cue_delete` seek, toggle, inspect and restore the playhead on separate ticks (the toggle used to run at the old playhead and a second `create_locator` crashed on the deleted cue), verify the playhead and the resulting cue time, and are refused inside `batch`.
- Found in Live 12.4.7 Lite (factory presets blocked): items reached through `sounds`, `drums` and `samples` have opaque `FileId` URIs without an extension, so every one was classified `user_content`. When the URI's last segment has no extension, the display name's extension now decides (samples allowed, presets with `allow_user_presets`); every block (.als, .amxd, Max for Live, External, plugin extensions) also applies to the name, folders Live says are not loadable report `blocked: null`, and the native Drum Rack device listed under `drums` is allowed.
- Found in Live 12.4.7 Lite: `song_set_time` and `cue_jump` reply one Live tick after the write (top level only; inside `batch` the reply still shows the playhead before Live applied it). `duplicate_to_arrangement` and `capture_session_to_arrangement` put the playhead back where it was after the copy (not while the transport plays). `destination_time` mixed with `source` now says to use `time`. An unanswered confirmation says nobody answered within N seconds (`details.reason` `timeout`), and confirmations name the device instead of only its index. Tool descriptions say that loop and marker times of an unwarped audio clip are in seconds, and that cue create/delete cannot run inside `batch`.
- Found in Live 12.4.7 Lite (F-T9-23, damage risk): `save_set_as` put the whole path in the Save panel's name field, so macOS kept the panel's folder and saved a file named `:Users:...:a.als` in the wrong place. It now goes to the requested folder first (Go to folder sheet set through accessibility, then Return), checks that `Where:` shows that folder, sets only the file name and reads it back, and presses Save only after both checks; any failed check cancels the panel and nothing is saved (`path_not_applied` with what was seen). The only key events in any host script are Cmd-Shift-G and Return, sent only while Live is the frontmost app with the panel open. Live's `<name> Project/<name>.als` layout is accepted by the post-save check (the result `path` is the file written, `requested_path` the one asked for) and by the overwrite check.
- Edition detection on Live Lite 12.4.7: its version string carries no edition, so with `edition: "auto"` the server now sends the edition of the running Live app as the hint (no start, 2 s bound; no hint when zero or two apps run). The host status also reports the running app after a connect.

- F-T9-28: `analyze_audio` and `compare_audio` read any absolute WAV/AIFF path when no `sample_roots` or `ears.roots` is configured (all other file checks stay); configured roots still narrow.
- `browser.allow_user_presets` now defaults to true so factory presets that Live lists as plain files (Sounds, Drums) load with no configuration; an explicit `false` still blocks them.
- F-T9-30: every tool with a single track, scene, clip or device selector (`get_mixer`, `list_clip_slots`, `duplicate_scene`, `get_slot_status`, `get_clip_info`, `list_devices`, ...) also takes `track_index` / `scene_index` / `clip_index` / `device_index`.
- F-T9-31: a `batuta_ears` or `record_and_analyze` job cancelled by the client reports `error_code: "cancelled"` in `batuta_status`.
- Tool error results show the error's `details` as a compact JSON line after the `code: message` line (for example the resource, limit, current and edition of `edition_limit`).
